# ADR 0001：管理员私密通知中的客户端 IP 明细

- 状态：Accepted
- 日期：2026-07-30

## 背景

原监控只通知近期公网 IP 数量，无法直接判断这些 IP 来自主节点还是远程节点，也没有
地区和运营商信息。超级管理员确认通知目标只有本人，并明确授权在异常通知中加入
完整 IP 和来源信息。

IP 属于敏感运维数据。现有监控状态文件用于告警去重，不应因此变成一份可长期检索的
IP 历史记录。调用公网 IP 查询 API 还会把访问 IP 泄露给新的第三方。

## 决策

1. 新能力采用显式开关 `client_ip_details.exposure`，默认值为 `none`；只有设为
   `full` 才生成明细。
2. 明细包含 IP、采集来源、窗口内首次/最近出现时间，以及国家、省/州、城市和
   运营商。来源取自 3x-ui 的主节点表或远程节点 GUID 对应的节点名称。
3. 归属查询使用离线 `ip2region` IPv4 数据，不向外部查询服务发送 IP。安装器固定
   上游提交和每个文件的 SHA-256，并保留上游许可证。
4. 单条通知最多展示 `max_entries` 个 IP，配置允许范围为 1–20，默认 8。归属库
   缺失、损坏、权限不安全或查询失败时显示“归属：暂不可用”，主监控继续运行。
5. 原始 IP 只存在于当次运行内存、`--dry-run --json` 输出和发往 AlertBridge 的
   通知正文。`state.json` 只保存聚合描述，不保存明细；恢复通知也不包含历史 IP。
6. 当前离线库只提供 IPv4 地区和运营商，不提供 ASN。IPv6 仍按 `/64` 统计和展示，
   归属信息暂不可用。

## 影响

- AlertBridge 及最终私密通知渠道会在各自保留周期内保存通知正文，因此若通知目标
  将来增加其他成员，必须先把 `exposure` 改回 `none` 并重新评估权限与保留周期。
- 在生产环境开启明细前必须先安装并验证离线库；数据库版本和生成时间记录在
  `/usr/local/share/threexui-script-monitor/ip2region-version.txt`。
- 不增加外部 IP 查询 API、ASN 查询、自动封禁或自动修改 3x-ui 的行为。
