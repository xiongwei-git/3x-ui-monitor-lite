# ADR 0003：按节点合并可用性通知

状态：Accepted

日期：2026-09-22

## 背景

同一次节点故障会同时产生状态、心跳、Xray 等多个异常与恢复通知；配置待同步
和资源类提醒进一步增加干扰。用户明确要求仅保留不可用与恢复两类事件。

## 决策

- 保留原始只读检查，将状态、心跳、Xray 原因按节点聚合。
- 连续两次有效采样确认，不对原因变化或持续时间重复提醒；恢复仅一次。
- 本机 3x-ui 服务使用独立的聚合事件，其他检查仅记录。
- 数据缺失、删除和停用不等于恢复；恢复必须来自有效且健康的采样。
- 新事件键与旧检查项事件键隔离，静默退休旧状态，避免迁移产生恢复消息风暴。
- 保留旧配置的 repeat_alert_seconds 兼容性，但不再使用其触发重复通知。
- journal 留下仅含脱敏异常键和事件类型的逐次观察记录。

## 备选方案与影响

仅修改标题不能解决多个事件和多条恢复；逐检查项延迟也不能合并故障，因此不采用。
默认周期下告警确认延迟约 5–10 分钟；长期未恢复故障不再定时催办。unknown 仍
作为不可用条件，但保留真实原因并明确管理面检查边界。持续时间为采样近似值。
旧 AlertBridge incident 不自动关闭或删除。通知失败仍重试；网络响应不确定时
不承诺端到端 exactly-once，网关去重语义仍由所选通知通道提供。
